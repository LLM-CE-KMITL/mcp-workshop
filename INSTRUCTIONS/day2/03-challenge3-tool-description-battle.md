# โจทย์ที่ 3 · Tool Description Battle

**11:35 – 12:00** (25 นาที) · ปิดช่วงเช้าวันที่ 2

---

## เป้าหมายการเรียนรู้

พิสูจน์ด้วยตัวเลขว่า **การแก้ description อย่างเดียว** เปลี่ยนความแม่นในการเลือก tool ได้แค่ไหน — โดยไม่แตะโค้ดของ tool เลย

---

## สถานการณ์

มีคนส่ง tool มาให้ 4 ตัวที่หน้าที่ทับซ้อนกันโดยตั้งใจ และเขียน description ไว้แย่ ผลคือ agent เลือกผิดเป็นประจำ

งานของคุณคือแก้ description ให้โมเดลเลือกถูก **ห้ามแก้โค้ดของ tool และห้ามลบ tool ทิ้ง**

---

## สิ่งที่ให้มา

`data/challenge_fixtures/tool_selection_cases.json` — คำถามทดสอบ 12 ข้อพร้อมเฉลยว่าควรเรียก tool ไหน

4 tool ที่ description แย่ (จงใจเขียนให้กำกวมและทับซ้อนกันเป็นคู่ — สังเกตว่า `search_tickets` กับ `search_tickets_semantic` ใช้ประโยคเดียวกันเป๊ะ เช่นเดียวกับ `search_logs` กับ `search_docs_semantic`):

```python
{"name": "search_tickets",          "description": "ใช้เครื่องมือนี้สำหรับการค้นหาข้อมูลทั่วไปเกี่ยวกับระบบเครือข่ายและอุปกรณ์ต่างๆ"}
{"name": "search_logs",             "description": "ใช้เครื่องมือนี้สำหรับการค้นหาข้อมูลทั่วไปเกี่ยวกับปัญหาหรือเรื่องที่เคยเกิดขึ้น"}
{"name": "search_tickets_semantic", "description": "ใช้เครื่องมือนี้สำหรับการค้นหาข้อมูลทั่วไปเกี่ยวกับระบบเครือข่ายและอุปกรณ์ต่างๆ"}
{"name": "search_docs_semantic",    "description": "ใช้เครื่องมือนี้สำหรับการค้นหาข้อมูลทั่วไปเกี่ยวกับปัญหาหรือเรื่องที่เคยเกิดขึ้น"}
```

---

## สิ่งที่ต้องทำ

### 1. วัดคะแนนตั้งต้น

```bash
uv run pytest tests/test_tool_selection.py -s
```

จดคะแนนไว้ (คาดว่าจะได้ประมาณ 4-6 จาก 12)

### 2. แก้ description

แก้ที่ `data/challenge_fixtures/tool_selection_cases.json` ในส่วน `descriptions_under_test`

**ใช้กฎจาก Module 5**
- บอกว่าเมื่อไหร่ห้ามใช้ และควรใช้ตัวไหนแทน
- บอกว่าคืนอะไร
- ฝังความรู้เชิงปฏิบัติที่ช่วยตัดสินใจ

### 3. วัดใหม่

```bash
uv run pytest tests/test_tool_selection.py -s
```

### 4. หาจุดที่ยังพลาด

ข้อไหนที่ยังผิดอยู่ ให้วิเคราะห์ว่าทำไม — บางครั้งปัญหาไม่ได้อยู่ที่ description แต่อยู่ที่ **การออกแบบ tool ที่ทับซ้อนกันตั้งแต่แรก**

## เกณฑ์ผ่าน

- [ ] คะแนนหลังแก้ **อย่างน้อย 10/12**
- [ ] เขียนได้ว่าคะแนนเพิ่มจากเท่าไหร่เป็นเท่าไหร่
- [ ] ทุก description ต้องมีประโยค "ห้ามใช้เมื่อ..." อย่างน้อย 1 ประโยค
- [ ] ระบุข้อที่ยังพลาดพร้อมเหตุผล
- [ ] ไม่ได้แก้โค้ดของ tool

## โบนัส

1. **ทดสอบว่าอันไหนมีผลมากที่สุด** — ลองใส่ทีละส่วน (เฉพาะ "ห้ามใช้เมื่อ" / เฉพาะ "คืนอะไร") แล้วดูว่าคะแนนขยับเท่าไหร่
2. **ยุบ tool** — ถ้าให้ยุบจาก 4 เหลือ 3 ตัวได้ จะยุบคู่ไหนและออกแบบ argument อย่างไร
3. **ทดสอบกับโมเดลเล็ก** — `baai/bge-m3` ได้คะแนนเท่าไหร่ description ที่ดีช่วยโมเดลเล็กได้มากกว่าหรือน้อยกว่าโมเดลใหญ่
