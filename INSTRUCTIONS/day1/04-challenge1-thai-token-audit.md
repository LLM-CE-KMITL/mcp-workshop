# โจทย์ที่ 1 · Thai Token Audit

**11:35 – 12:00** (25 นาที) · ปิดช่วงเช้าวันที่ 1

## เป้าหมายการเรียนรู้

พิสูจน์ด้วยตัวเลขจากข้อมูลจริงว่า **ภาษาไทยใช้ทรัพยากรมากกว่าภาษาอังกฤษเท่าใด** และ **tokenizer ผิดรุ่นให้ตัวเลขคลาดเคลื่อนมากน้อยเพียงใด**

โยงกลับ Module 1 · เตรียมพื้นสำหรับการตัดสินใจเรื่อง chunking ในวันที่ 3

---

## สถานการณ์

ทีมกำลังวางแผนทำ semantic search บนประวัติ ticket ทั้งหมด หัวหน้าทีมตั้งคำถามว่า *"ถ้าจะทำกับ ticket ทั้งระบบ 2,600 อุปกรณ์ จะต้องใช้ทรัพยากรเท่าใด และมีประเด็นใดที่ควรระมัดระวัง"*

## สิ่งที่ให้มา

- ฐานข้อมูล ticket 120 ใบ (ไทย, อังกฤษ และไทยปนอังกฤษ)
- `apps/agent-api/agent/tokenizer.py` — มี `count()` และ `compare()` ให้แล้ว

## สิ่งที่ต้องทำ

### 1. ดึงข้อมูลมา 50 ใบ แล้วแยกกลุ่ม

```sql
SELECT ticket_id, title, description FROM tickets ORDER BY random() LIMIT 50;
```

แยกเป็น 3 กลุ่ม: **ไทยล้วน / อังกฤษล้วน / ปนกัน**
(เกณฑ์อย่างง่าย: นับสัดส่วนอักขระไทยเทียบกับจำนวนอักขระทั้งหมด)

### 2. นับ 3 วิธีเทียบกัน

ใช้ `tokenizer.compare()` แล้วทำตารางนี้:

| กลุ่ม | จำนวนตัวอักษร | คำ (pythainlp) | **token (Qwen)** | token (tiktoken) | tiktoken ผิดกี่ % |
|---|---|---|---|---|---|
| ไทยล้วน | | | | | |
| อังกฤษล้วน | | | | | |
| ปนกัน | | | | | |

### 3. คำนวณอัตราส่วนที่ใช้ตัดสินใจได้จริง

- token ต่อ 1 ตัวอักษร ของแต่ละกลุ่ม
- **token ของข้อความไทย เป็นกี่เท่าของอังกฤษ** เมื่อจำนวนตัวอักษรเท่ากัน
- ถ้าจะ embed ticket ทั้ง 120 ใบ ใช้ token รวมเท่าไหร่

### 4. ประมาณการขึ้น production

สมมติ 2,600 อุปกรณ์ มี ticket เฉลี่ยอุปกรณ์ละ 30 ใบต่อปี

- token รวมต่อปีเป็นเท่าไหร่
- หากระบบ embedding ประมวลผลได้ประมาณ 500 ข้อความ/วินาที การ embed ครั้งแรกทั้งหมดจะใช้เวลานานเท่าใด
- ถ้าต้อง re-embed ทุกครั้งที่เปลี่ยนโมเดล จะเจอปัญหาอะไร

### 5. เสนอ 1 ข้อ

เสนอวิธีลดต้นทุน 1 ข้อ พร้อมตัวเลขรองรับ

## เกณฑ์ผ่าน (Definition of Done)

- [ ] ตารางเปรียบเทียบครบ 3 กลุ่ม × 3 วิธีนับ
- [ ] ระบุได้ว่า **tiktoken ให้ตัวเลขคลาดเคลื่อนกี่เปอร์เซ็นต์** เมื่อใช้กับ Qwen
- [ ] มีตัวเลข "token ไทยเป็นกี่เท่าของอังกฤษ"
- [ ] ประมาณการ scale production พร้อมสมมติฐานที่เขียนไว้ชัดเจน
- [ ] ข้อเสนอลดต้นทุน 1 ข้อ พร้อมตัวเลขรองรับ

## โบนัส (สำหรับคนทำเร็ว)

1. วัดว่า**การ chunk ด้วยจำนวนตัวอักษร**ทำให้จำนวน token ต่อ chunk แปรผันมากน้อยเพียงใดระหว่างภาษาไทยกับภาษาอังกฤษ แล้วเสนอวิธี chunk ที่เหมาะสมกว่า
2. หา ticket ที่มีสัดส่วน token ต่อตัวอักษรสูงที่สุด แล้ววิเคราะห์หาสาเหตุ (คำเฉพาะทาง? เลขวงจร? ภาษาปน?)
3. เทียบ `newmm` กับ `attacut` ของ pythainlp ว่าตัดคำต่างกันอย่างไร

<details>
<summary>Hint (เปิดเมื่อติดเกิน 10 นาที)</summary>

- แยกภาษาแบบง่าย: `sum(1 for c in text if '฀' <= c <= '๿') / len(text)` > 0.5 ถือว่าไทย
- ถ้าโหลด Qwen tokenizer ไม่ได้ (ออฟไลน์) `tokenizer.count()` จะ fallback เป็นสูตรประมาณ ใช้ได้แต่ต้องระบุในรายงานว่าเป็นค่าประมาณ
  อีกทางเลือกคือเช็คจำนวน token จริงผ่านเว็บ (ไม่ต้องติดตั้งอะไร): https://huggingface.co/spaces/Xenova/the-tokenizer-playground — เลือก tokenizer ของโมเดลที่ตรงกัน แล้ววางข้อความเทียบได้เลย
- โปรดสังเกตว่า `description` ยาวกว่า `title` มาก จึงควรรวมข้อมูลจากทั้งสองฟิลด์เข้าด้วยกัน
</details>
