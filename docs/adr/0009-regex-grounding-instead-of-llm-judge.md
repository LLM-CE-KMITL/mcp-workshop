# ADR-009: Grounding แบบ regex แทน LLM-judge

- สถานะ: Accepted
- วันที่บันทึก: 2026-11-01 (บันทึกย้อนหลังจากโค้ดที่ใช้งานอยู่ ไม่ใช่เอกสารต้นฉบับของผู้ออกแบบ)
- ADR ที่เกี่ยวข้อง: [ADR-010](0010-scenario-first-deterministic-dataset.md)

- **บริบท:** ความเสี่ยงหลักคือคำตอบที่ "มั่นใจแต่ผิด" ซึ่งเป็นจุดที่ LLM-judge พลาดได้เช่นกัน เช่น S4 ที่ข้อเท็จจริงจริงแต่ข้อสรุปผิด
- **ตัดสินใจ:** ใช้ [verifier.py](../../apps/agent-api/verifier.py) ตรวจด้วย regex และกฎ: device ID/ticket ID/ตัวเลขร้อยละที่ไม่อยู่ในหลักฐาน, ภาษาแบบเหตุเสียทั้งที่มี ticket maintenance (ยกเว้นเมื่อมีคำแสดงความไม่แน่นอนหรือคำปฏิเสธใกล้กัน), ปีที่อยู่นอกช่วงหลักฐาน ตรวจเสร็จไม่ทำให้เทิร์นล้ม (ถ้าตัวตรวจพังจะคืน `supported=true` พร้อมหมายเหตุ)
- **ผลที่ตามมา:** (+) ถูก เร็ว ทำซ้ำได้ ไม่ใช้ token (−) จับได้เฉพาะรูปแบบที่เขียนกฎไว้ ใช้หน้าต่างอักขระ 40 ตัว เพราะภาษาไทยไม่มีขอบเขตคำที่ใช้กับ regex ได้ตรงๆ ตัวตรวจแบบ LLM ใน `agent/grounding.py` ยังอยู่แต่ไม่ถูกใช้ ([AGENTS.md หัวข้อ 7](../../AGENTS.md#7-ปัญหาและข้อสังเกตที่ทราบแล้ว) ข้อ 1) ควรตัดสินใจว่าจะลบหรือใช้เป็นชั้นเสริม
